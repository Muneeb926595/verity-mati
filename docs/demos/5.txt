Your question
  What happens if GPS becomes unavailable?

Answer
  When GPS data stops arriving, NavigationTick() detects the loss after 2000 ms and sets `g_nav.mode
  = NAV_MODE_HOLD`, then calls VehicleController_Hold() which sets `s_last_command_deg = 0.0`, calls
  `motor_set_steering(0)`, and calls `led_set_status(0)`. This stops bearing_deg() and
  VehicleController_SetDirection() from running, so the vehicle holds its current position. If
  ENABLE_DEAD_RECKONING is defined, NavigationTick() would instead set `g_nav.mode =
  NAV_MODE_DEAD_RECKONING` and continue processing.

  Losing the data is detected in NavigationTick() (nav/navigation.c:68), which checks `g_nav.has_fix
  && (now_ms - g_nav.last_fix_ms) > GPS_TIMEOUT_MS` (GPS_TIMEOUT_MS = 2000).

  When that happens it sets `g_nav.mode = NAV_MODE_HOLD`; calls VehicleController_Hold() (which sets
  `s_last_command_deg = 0.0` (line 25), calls motor_set_steering(0) (line 26), calls
  led_set_status(0) (line 27)); returns, so bearing_deg(), VehicleController_SetDirection() no
  longer run.

  Note that this only triggers when all of these hold: `g_nav.has_fix`; `(now_ms -
  g_nav.last_fix_ms) > GPS_TIMEOUT_MS`. For example, when `g_nav.has_fix` is false this path is not
  taken.

  NavigationTick() also stops early when `g_nav.mode != NAV_MODE_TRACKING && g_nav.mode !=
  NAV_MODE_DEAD_RECKONING` (line 77), which skips bearing_deg(), VehicleController_SetDirection() —
  so without fresh valid data it does not reach those calls either.

  This behaviour depends on the build configuration: ENABLE_DEAD_RECKONING is not defined anywhere
  in the code, so by default the path above is taken. If ENABLE_DEAD_RECKONING is defined when
  building, it instead sets `g_nav.mode = NAV_MODE_DEAD_RECKONING` and keeps going.

  I ran the real code in a sandbox (one good input, then no data for 2100 ms) with latitude = 0.0,
  longitude = 0.0, speed_knots = 4, hdop = 1.25, satellites = 8, valid = 1.

  Functions that ran, in order: ProcessGpsData() → gps_validate_fix() → CalculateHeading() →

  gps_validate_fix(): `fix == 0 || !fix->valid` was false (line 7), `fix->latitude < -90.0 ||
  fix->latitude > 90.0 || fix->longitude < -180.0 || fix->longitude > 180.0` was false (line 10),
