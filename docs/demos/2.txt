  What does ProcessGpsData() do?

Answer
  ProcessGpsData() validates a GPS fix, updates navigation state, calculates a heading, and sets the
  mode to tracking. If the fix is invalid it calls nav_handle_invalid_fix() and returns. It is
  invoked via the callback chain from main to handle_rmc().

  ProcessGpsData() (nav/navigation.c:45) — Entry point for every decoded GPS fix (registered as the
  GPS receiver callback in main).

  Step by step, it calls gps_validate_fix(fix) and stores the result in `status` (line 47); then it
  checks `status != GPS_OK` (GPS_OK = 0) (line 49); if true it calls nav_handle_invalid_fix() and
  stops there (returns); then it updates g_nav (consecutive_invalid, latitude, longitude,
  speed_knots, last_fix_ms, has_fix; lines 53–58); then it calls CalculateHeading(fix->heading_deg,
  fix->speed_knots) and stores the result in `currentHeading` (line 59); then it sets `g_nav.mode =
  NAV_MODE_TRACKING` (line 60).

  It is called by handle_rmc() (through the function pointer g_fix_callback) at
  gps/gps_receiver.c:76 (ProcessGpsData() is registered at app/main.c:16) with (`&fix`), only when
  `s->field_count < 8` is false, only when `g_fix_callback != 0` is true. The full chain from the
  program's start is: main() → gps_receiver_poll() → gps_receiver_process_line() → handle_rmc() →
  ProcessGpsData().

  The values it updates are used later by NavigationTick() (uses currentHeading,
  nav_state_t.has_fix, nav_state_t.last_fix_ms, nav_state_t.latitude); nav_handle_invalid_fix()
  (uses nav_state_t.consecutive_invalid); CalculateHeading() (uses currentHeading).
